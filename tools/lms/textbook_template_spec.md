# 교과서 업로드 템플릿 규격 — `textbook_template.xlsx`

> 원본: claude.ai 프로젝트 문서 `claude/textbook_template_spec.md` (2026-10-19 갱신).

**2026-10-19 실제 LMS 업로드 실패 → 아래 §7의 오류 해석을 먼저 읽을 것.**

## 0. 워크북 구조
- 시트: `TextbookTemplate`(visible) + `_Lookup`(hidden)
- `_Lookup` 열: A 정답유형·비교유형 / B 난이도 / C 아니오·예 / D 단위 / E 공개여부 /
  F 편집유형 / G 학년

## 1. 상단 (1~8행)
```
1행: 교재명 | 과목
2행: <교재명> | 수학
3행: 출판일 | 출판사 | 편집 유형 | 학년 | ISBN | 공개 여부 | 모의고사 여부 | 모의고사 문항 수 | 모의고사 시간
4행: 값   (편집 유형·학년·공개 여부·모의고사 여부는 _Lookup F/G/E/C 값)
5~8행: 공백
9행부터: 대단원 → 소단원 → (그룹헤더 → 그룹데이터 → 문항헤더 → 문항데이터) 반복
```

## 2. 대단원 / 소단원 행 — 4열
```
A='대단원' | B=<이름> | C=pageFrom(int) | D=pageTo(int)
A='소단원' | B=<이름> | C=pageFrom(int) | D=pageTo(int)
```

## 3. 그룹 헤더 행 — **7열**
```
그룹 순서 | 대분류 | 소분류 | 유형 | 지문 제목 | 지문 작성자 | 지문 태그
```
- **그룹 순서: 파일 전체에서 1부터 통산.** 소단원마다 1로 재시작하면 LMS가 서로 다른
  소단원의 문항을 같은 "지문 그룹"으로 묶어버린다 (2026-10-19 실측)
- 지문 제목, 지문 작성자 `지영T`, 지문 태그 = 과목명(`확률과 통계` 등)
- 8열 이상에 셀을 만들지 않는다 (고스트 셀 금지)

## 4. 문항 헤더 행 — **13열** (K열이 `정답단답형`, 비교 유형 열 없음)
```
A 문항 번호 | B 대분류 | C 소분류 | D 유형 | E 정답유형 | F 난이도 | G 권장풀이시간(mm:ss) |
H 답안개수 | I 점수 | J 정답선택지 | K 정답단답형 | L 단위 | M 답안없음
```
| 열 | 값·타입 |
|---|---|
| A | **파일 전체 통산 순차 문자열** `'1'`…`'N'`, `number_format="@"` |
| E | `단일 선택` / `다중 선택` / `단답형` |
| F | `일반적인 문제` 등 _Lookup B 값 |
| G | `datetime.time`, `number_format="mm:ss"` |
| H | **문자열** — 객관식 `'5'`, 단답형 `'1'` |
| I | **int** |
| J | **문자열** — 객관식 정답 번호 |
| K | 단답형 정답, HTML 래핑 금지 |
| L | 단위 (필요 시만) |
| M | `아니오` |

## 5. 빌드 파이프라인
1. `templates/textbook_template.xlsx` 복사 → `ws.delete_rows(9, max_row)` (`_Lookup` 유지)
2. 1~4행 메타 기입 후 9행부터 블록 반복
3. 고스트 셀 제거: 저장 전 `ws._cells`에서 value가 None인 키 전부 `del`
4. 자기닫힘 `<c .../>` 0건 확인
5. LMS 업로드 파일명 ASCII, 저장 경로 `out/`

## 6. 검증
`scripts/validate_lms_upload.py`는 **시험 v3(9열/14열) 전용**이라 교과서 파일에 그대로 쓰면
그룹 헤더 7열을 ERROR로, 문항 헤더 13열을 HEADER-ITEM-V1 WARNING으로 잘못 보고한다.
교과서 파일은 7열/13열 기준 별도 검증기로 확인할 것.

## 7. ★ 2026-10-19 실제 업로드 실패 — 오류 해석 (중요)

마더텅 확통 I. 순열과 조합 383문항 교과서 파일을 올렸더니 오류 605건. 내역:

| 오류 문구 | 건수 | 해석 |
|---|---|---|
| `잘못된 Excel 헤더 이름 '교재명' (1열) (행 1)` | 1 | 1행에 `시험 제목·과목·시험 시간(분)`을 기대 |
| `시험 기간은 필수 항목입니다 (3열, 행 2)` | 1 | 같은 원인 |
| `단위 '아니오'이(가) 유효하지 않습니다. (13열)` | 383 (전 문항) | **13열을 `단위`로 읽음** — 시험 v3는 13열=단위·14열=답안없음, 교과서는 13열=답안없음 |
| `시험 문제의 순서는 순차적이지 않습니다 (1열)` | 220 (= 2·3단원 문항 수) | 문항 번호를 소단원마다 001로 재시작 |

**결론: LMS가 이 파일을 시험(Exam) 파서로 읽었다.** 네 오류가 전부 그 한 가지로 설명된다.
교재 파일을 시험 업로드 메뉴에 넣었거나, LMS에 교과서 전용 파서가 (더 이상) 없거나 둘 중 하나.

오류 로그가 "지문 그룹 1"에 행 14·667·1208을 함께 묶은 것은 세 소단원의 **그룹 순서가 모두
1부터 재시작**한 탓. 행 번호 계산: 9=대단원, 10=소단원1, 11~14=1번 문항 블록, 이후 4행씩 →
소단원1(163문항) 11~662, 663=소단원2, 667=소단원2 첫 문항, 1204=소단원3, 1208=소단원3 첫 문항.
로그와 정확히 일치.

### 교정 내용 (v2)
- 그룹 순서를 1~383 통산으로 변경
- 문항 번호를 1~383 통산 순차로 변경 (책의 소단원별 번호는 `지문 제목`에
  `여러 가지 순열 001번` 형태로 보존)

### 동시에 제작한 대안 — 시험 양식 v3 3종
교과서 파서가 없을 경우를 대비해 **소단원별 독립 시험**으로도 만들었다. 소단원으로 쪼개면
책 번호가 그 자체로 1..N 순차가 되어 번호 재매핑이 필요 없다.

| 파일 | 문항 | 시험 시간 | 배점 |
|---|---|---|---|
| `Madertong_ProbStat_2027_I1_Sunyeol_Exam.xlsx` | 163 | 433분 | 549점 |
| `Madertong_ProbStat_2027_I2_Jungbokjohap_Exam.xlsx` | 135 | 463분 | 491점 |
| `Madertong_ProbStat_2027_I3_Ihangjeongri_Exam.xlsx` | 85 | 166분 | 262점 |

시험 시간은 권장풀이시간 합계를 올림한 값. 실제 시험 시간이 아니라 교재 단원 전체의
풀이시간 총량이므로, LMS에서 타이머로 쓰인다면 더 잘게 쪼개야 한다.

### 다음 업로드 전 반드시 확인할 것
- [ ] 그룹 순서가 파일 전체 1~N 통산인가
- [ ] 문항 번호가 파일 전체 1~N 순차 문자열인가
- [ ] 단위 열(교과서 L / 시험 M)이 비어 있는가 — 여기에 `아니오`가 들어가면 열이 하나 밀렸다는 신호
- [ ] 올리려는 메뉴가 교재용인가 시험용인가 (양식이 다르다)
