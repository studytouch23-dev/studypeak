> 상태: **기획 단계 — 아직 코드 없음.** 사용자(한지영 선생님) 확인 후 1단계부터 만든다.

**AI의 국어 풀이 실력**: 최신 모델이 수능 국어 만점을 받았다는 보도와, 같은 시기 40~50점대라는 연구가 함께 있다(모델·지시 방식에 따라 편차가 큼). → 생성물은 **반드시 독립 검증**을 거친다.

**비어 있는 자리(우리 차별점)**: 찾은 AI 서비스는 모두 "글감 → 새 지문"이 중심. **내가 가진 시험지(PDF·캡처)를 지문·문항 세트로 DB화 → 그 지문으로 변형 → 근거 검증 → 한글 파일 → 스터디피크 LMS**까지 한 번에 이어지는 개인 DB형 도구는 찾지 못함.

## 2. 수학과 다른 점 (설계에 반영)

1. **단위가 세트**: 지문 1개에 문항 2~6개([1~3] 다음 글을 읽고…). 지문 없는 단독 문항(문법·화법 일부)도 있음.
2. **지문 표시**: 밑줄 ㉠~㉤, ⓐ~ⓔ, [A]·[B] 구간, (가)(나) 복합 지문, 시의 연·행, <보기> 상자, 표. 수식은 거의 없음.
3. **세트가 단·쪽을 넘어감**: 수능 국어는 2단, 지문이 다음 단·다음 쪽으로 이어짐 → 영역 인식에 "이어짐" 병합 필요(수학 해설 이어짐 로직 응용).
4. **변형의 의미가 다름**: 숫자 바꾸기가 아니라 선지 재구성·유형 전환·<보기> 교체·서술형 전환·OX 분해·새 지문.
5. **검증 방식이 다름**: 다시 계산이 아니라 **선지별 근거 문장**이 지문에 실제로 있는지, 정답이 정확히 1개인지.
6. **저작권**: 문학 작품·교과서·EBS 지문. 지문마다 출처·이용 메모를 남기고, 독서 지문은 새로 생성하는 길도 제공.
7. **LMS**: 엑셀 양식의 "그룹(지문)" 칸이 이제 실제로 쓰임(지문 제목·작성자·태그). 국어는 유형ID 접두사 규칙 등이 따로 있음(국어 프로젝트 지침 필요).

## 3. 데이터 모델

```
Passage 지문  { id, area(독서·문학·화법·작문·언어·매체), genre(인문/사회/과학/기술/예술 · 현대시/고전시가/현대소설/고전소설/극·수필 …),
               title, author, body(표시 문법 포함), parts[(가)(나)], images[], source{종류(교과서·EBS·기출·자체), 출판사·단원 / 시험 연·월·학년},
               license(저작권 메모), analysis{주제, 문단 요약, 핵심어, 문학: 화자·정서·표현}, tags[], hash(중복 검사), createdAt … }
Item 문항     { id, passageIds[](없으면 단독), order, stem(발문), view(<보기>), choices[5], answer, explain, evidence[선지별 {판정, 근거 인용}],
               answerType(단일·다중·단답·서술), rubric(서술형 채점 기준), spType(스터디피크 국어 유형), difficulty, points, origNo,
               variantOf, variantKind, verify{blind, evidence, unique}, reviewed, batch … }
Sheet 학습지  { id, title, entries[{passageId, itemIds[]}] | 단독 문항 }  — 지문과 문항이 떨어지지 않게 세트 단위로 담는다
```

본문 표시 문법(가볍게): `{u:㉠}…{/u}` 밑줄, `{b}…{/b}` 굵게, `[A[`…`]A]` 구간, `[박스]…[/박스]`(수학 랩과 동일), `[보기]…[/보기]`, 시 행은 줄바꿈 유지.

## 4. 흐름 (수학 랩과 같은 뼈대)

1. **올리기**: PDF·HWPX·캡처(Ctrl+V). `[N~M]` 머리말과 문항 번호로 **지문 영역 + 문항 영역**을 자동 인식, 단·쪽 이어짐 병합, 손으로 고치기.
2. **AI 변환**: 지문·문항 이미지를 글로(밑줄·기호·<보기> 보존). 원본 조각을 옆에 두고 검수.
3. **자동 분류**: 영역·갈래, 작품명·작가, 스터디피크 국어 유형, 난이도. 같은 지문이 이미 있으면 그 지문에 붙임(중복 검사).
4. **변형 만들기** (종류를 골라서)
   - 쌍둥이: 같은 지문·같은 유형, 선지 재구성(정답 위치·오답 근거 교체)
   - 유형 전환: 같은 지문으로 다른 유형(내용 일치 ↔ 추론 ↔ <보기> 적용 ↔ 표현상 특징 ↔ 어휘)
   - OX 분해: 선지 하나하나를 O/X 문항으로(내신 대비용)
   - 서술형 전환: 조건 있는 서술형 + 모범 답안 + 채점 기준
   - <보기> 새로 쓰기: 외적 준거를 바꾼 감상·적용 문항
   - 새 지문(독서만): 같은 제재·구조의 새 글 + 세트 문항 (저작권 부담 없음)
5. **검증** (통과한 것만 저장, 실패는 한 번 수리 후 재검증)
   - 블라인드 풀이: 정답을 가린 다른 호출이 풀어 일치 확인
   - 선지별 근거: 선지마다 판정 + 지문 인용 → **인용문이 지문에 실제로 있는지 코드로 대조**
   - 유일 정답: 5개 선지를 각각 독립 판정해 정답이 정확히 1개인지
   - 오답 규칙: 오답마다 틀린 지점이 한 곳인지(너무 뻔하거나 논란 여지 있는 선지 표시)
6. **출력**: 학습지(2단, 세트 유지), 수능형 모의고사 양식, 정답·해설(선지별 근거), HWPX(밑줄·상자), LMS 엑셀(지문 = 그룹).

## 5. 화면 (수학 랩과 같은 초록·Pretendard 틀)

왼쪽 메뉴: 대시보드 / **지문·작품** / 문제 등록 / 문제 검색·작업 / AI 작업(변형 만들기·생성 내역) / 학습지·모의고사 / 태그 관리(영역·유형 · 출처 · 나만의 태그) / 백업·데이터.

- **세트 상세**: 왼쪽 지문(밑줄·기호 강조) · 오른쪽 문항 목록. 선지를 누르면 근거 문장이 지문에서 강조됨.
- **변형 만들기**: 지문 고르기 → 종류·유형·개수·난이도 → 실황(만드는 중·검증 중·저장) → 결과 묶음.
- **지문·작품**: 작품 카드(갈래·작가·출처·문항 수·변형 수), 교과서 출판사·단원 / EBS / 기출 연도로 좁히기.

## 6. 코드 방향 (결정)

- **주소** `korlab/` → www.studypeak.co.kr/korlab/. 수학 랩(`lab/`)은 건드리지 않고 시작.
- **처음부터 파일을 나눈다**(빌드 도구 없이 `<script src>`): `korlab/index.html`(화면) + `korlab/js/` — core(저장·동기화·로그인·설정) · ai · upload(PDF 영역 인식) · passage · item · variant · verify · sheet · hwpx · lms · data(유형표).
  수학 랩의 10,800줄 한 파일 구조를 되풀이하지 않는다.
- **공용 조각은 `shared/`로**: 범용이고 독립적인 것(이스케이프·다운로드·xlsx 쓰기·AI 호출·IndexedDB·Supabase 동기화·설정 동기화)은 `shared/*.js`로 새로 정리해 국어가 먼저 쓰고,
  수학 랩은 국어가 안정된 뒤 테스트(63개)로 지키며 하나씩 옮긴다. (두 번째 사용처가 생긴 뒤에야 공용 인터페이스가 분명해지므로, 수학을 먼저 뜯지 않는다.)
- **저장**: IndexedDB(DB 이름 분리) + Supabase 같은 계정. 새 테이블 `kor_passages`·`kor_items`·`kor_sheets`(같은 RLS 규칙) — 사용자가 SQL을 한 번 붙여넣어 실행해야 함.
  API 키 등 설정은 기존 `__settings` 행을 그대로 읽어 **로그인만 하면 국어 랩도 바로 동작**.
- **테스트**: `tests/kor*.js` 스모크(실제 시험지 조각을 테스트 자료로), PR마다 GitHub Actions.
- **AI 비용 줄이기**: 지문은 한 번만 보내고 재사용(프롬프트 캐싱), 문항은 묶음 호출, 검증은 선지별 판정을 한 호출로.

## 8. 사용자에게 확인할 것

1. 먼저 맞출 대상: 고등 내신(교과서·수능특강) / 수능·모의고사 / 중등
2. 스터디피크 **국어 유형표**와 국어 프로젝트 지침(수학 때처럼 zip)
3. 샘플 시험지 2~3개(내신 기출 1, 모의고사 1) — 세트 인식 맞추기용
4. 가장 자주 만드는 변형 종류(2단계 우선순위)
